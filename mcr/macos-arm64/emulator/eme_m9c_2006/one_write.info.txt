# eme_m9c_2006/one_write — §1A.9 REACH-INDEPENDENT whole-program svc-capture
# via the FAST INLINE DETOUR tier (no per-syscall trap) one_write recording.
#
# Victim: write(1,"one\n",4); return 0;   (direct write syscall.)
#
# WHY THIS FIXTURE EXISTS
# ----------------------------------------------------------------------------
# The M9c whole-program svc-capture patcher routes each captured svc site
# through a per-site trampoline reached WITHOUT a per-syscall parent trap.
# The preferred tier is a `B`->island (±128 MiB).  For an image whose __text
# is wholly inside the dense dyld shared cache — notably `libsystem_kernel`
# (the 522-site syscall funnel) — some boot layouts leave NO ±128 MiB-reachable
# gap for the island, so island placement fails.
#
# The §1A.9 fix adds a TIERED, reach-INDEPENDENT per-site patch:
#   tier 1  B -> island        (fast, no trap; needs a ±128 MiB hole)
#   tier 2  ADRP DETOUR         (fast, NO trap; needs only a ±4 GiB hole) <== NEW
#           The svc site is overwritten with an 8-byte ABSOLUTE redirect
#           `ADRP X17,<stubpage> ; BR X17` (svc + 1 following instruction).
#           The overwritten following instruction is RELOCATED into a per-site
#           4 KiB-aligned stub whose body is the SAME guarded in-child capture
#           body the island tier uses (depth/thread guard, out-param capture,
#           real-svc re-issue, band append) followed by the relocated
#           instruction (PC-relative fields fixed up) and an absolute return
#           to site+8.  Because the redirect is a plain branch pair, EVERY
#           captured syscall stays entirely in-child — ZERO parent round-trips.
#   tier 3  BRK + handler       (4 bytes, no reach limit, but ONE PARENT TRAP
#           PER SYSCALL) — the LAST-RESORT fallback, used only for the
#           (empirically zero) residual sites whose following instruction the
#           detour relocator declines.  BRK is what this fixture USED TO use for
#           libsystem_kernel; the detour replaces it with a trap-free path.
#
# The following instruction after a libsystem_kernel svc is empirically always
# `b.cc` (the syscall error check, `0x54000103`) or `ret` — both relocated fast.
#

# RE-RECORDED 2026-07-30 — the out-param destination fix, and what moved
# ============================================================================
# Re-recorded with the committed driver after two recorder fixes landed
# (codetracer-native-recorder `metacraft-labs/dev`: an out-param rule must prove
# its destination is an address; a non-address the recording agrees with is not a
# divergence).  Why a re-record was REQUIRED rather than optional: under
# `--os-simulation=strong-userspace` the replay runs the injected HOOK IMAGE THAT
# THE RECORDING CAPTURED (`mbpRegionHookBlob` inside `t_start.bpat`), so a change
# to the hook's replay arm cannot reach an already-recorded trace at all.
#
# WHAT THE OLD RECORDING CONTAINED THAT WAS WRONG.  Its 4th
# `shared_region_check_np`(294) — event 1944 — carried an 8-byte "out-param" of
# ZEROS.  The guest legitimately calls that syscall with `x0 == -1` (verified: the
# emulator reads the same value out of the live guest registers at the same PC,
# and the site is dyld's own `__shared_region_check_np` stub), so there was no
# copyout to capture; capture rule 294 was unconditional and fabricated one.  In
# this recording that produced 8 zero bytes; in a normally-compiled recorder build
# the same rule SEGFAULTS the append, i.e. a syscall argument could kill a
# recording.  Event 1944 now correctly carries NO out-param.
#
# WHAT MOVED IN THE PINS, and the classification of each:
#   * strong-userspace `stopPC` 0x1002692B8 -> 0x18F259B58.  A REAL DEFECT WAS
#     FIXED.  The old stop was the re-issued `svc` inside the reconstructed
#     capture-stub region, reached because the hook refused the fabricated
#     out-param.  The new stop is `libsystem_kernel`'s `task_self_trap`, OUTSIDE
#     that region — the guest got past 1944 and is now blocked by a DIFFERENT,
#     named gap (see below).  Nothing else moved: cursor 1945, 1896 in-guest
#     restores, 49 emulator ring skips, zero emulator serves and the
#     consume-XOR-serve identity are all unchanged, and the stop is still an
#     honest hard-stop — so no regression is hidden behind the new number.
#   * the stub-region BOUND assertion flipped direction with the cause, and is
#     re-expressed as "outside the stub region, inside libsystem_kernel's
#     __TEXT", which is the B12 never-stubbed signature rather than the old
#     stub-ran-and-took-its-record-arm signature.
#   * `t_start.bpat` is now MBP1 v2 (128-byte image blocks, carrying a whole-file
#     content hash for the interpose dylib).  ACCEPTABLE — the record got richer.
#     COST, recorded because it is easy to miss: this was the only committed
#     fixture with a `t_start.bpat`, so no fixture exercises the v1 decode path
#     any more.  The v1 cases in `ct_events/tests/test_macos_bootstrap_patch.nim`
#     construct their records and so still cover it, but they are now the ONLY
#     coverage and must not be thinned out.
#   * DEFAULT-mode pins did NOT move: 2133 records, arc4 11, predyldServed 1935,
#     bsdMemoryOps 15, cursor 2009, stopPC 0x18F25A638.  Nor did strong-kernel,
#     per-thread-stream, commpage or determinism (now also asserted under
#     strong-userspace, 3 separate processes).
