# ETE DIFFERENTIAL ORACLE — NEGATIVE RESULT (this pass):
#   The plan was to decode this recording's .trace.ete via
#   ct_events/apple_ete.nim (appleRealControlFlowEvents) into an ordered
#   address-anchor stream and align-diff it against the replay PC trace to pin
#   the first divergent control-flow address. On this FULL 148 MB real stream

#     byte coverage       = 0.9056   (packet framing largely understood)
#     address anchors     = 121,400  (0.034% of 354M events; rest are atoms)
#     4-byte-aligned      = 34%       (valid ARM64 instruction VAs need 100%)
